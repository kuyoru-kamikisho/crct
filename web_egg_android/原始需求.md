由于公司很多项目都是web项目，但是又会遇到需要程序外壳的情况，比如点餐平板、自助采购平板、电子签名等需求，这时候就需要一个程序外壳来包裹web项目。

本项目用于解决此基础需求，以下是功能清单：

## 启动初始化

- 启动时，首先打开设置页，设置页支持以下配置：
  1. 项目名称 （字符串）
  2. 项目ID （字符串）
  3. 项目URL （字符串，软件启动时需要加载哪个web项目的URL）
  4. 软件运行时产生的日志的保存路径 （字符串，默认是软件启动目录的 ./logs/）
  5. 是否每次启动都全屏 （布尔值，默认是False，覆盖手机、平板刘海状态栏）
  6. 附加信息 （长文本输入框，字符串，支持换行，默认是空字符串，用于输入一些json之类的内容，web项目各种各样，web应用可以通过与软件通信来获得这个附加信息，并通过附加信息来配置任何专属信息）
  7. 自动更新地址 （字符串，默认是空字符串，用于自动更新软件，比如可以设置为 http://localhost:8080/update/）

  配置完成后需要将以上配置保存为配置文件，以后启动不再弹出设置页直接根据配置文件进入对应的URL；
  如果无配置文件则依然要打开设置页，用户可以通过手动删除配置文件来重新配置软件；
  其它配置项可以尝试帮我想想，尽可能地让软件提供多的通信API以便适配各种各样的web项目。

## 通信

- 软件与web项目之间的通信，web应用可以与软件互相发送消息来支持以下内容：
  1. web to 软件，关闭软件（退出程序）
  2. web to 软件，全屏
  3. web to 软件，向软件发送一些字符串并保存日志
  4. web to 软件，获取软件所有配置信息（包括附加信息）
  5. web to 软件，获取设备信息（比如屏幕分辨率、屏幕尺寸等、CPU等等）

  以上由web发起的通信，如果相关内容和软件配置项相关，则需要同步修改配置项并更新配置文件；
  其它通信内容可以尝试帮我想想，尽可能地让软件提供多的通信API以便适配各种各样的web项目。

## 性能与健壮性

- 若无web影响，软件应该尽可能地保持良好的性能，最好可以秒启动
- 尽可能地避免软件在运行时崩溃或异常退出

## 安装程序

- 软件最终应该可以被打包为一个.app安装程序，以便于交付给客户

## 软件自动更新

- 示例：假如初始化时填写的自动更新地址是 "http://www.baidu.com/update/",
  则软件启动时会尝试获取该地址下的 version.json 文件比如 "http://www.baidu.com/update/version.json"
  下面是这个json文件的格式：
  ```json
  {
    "version": "1.0.3",
    "download_url": "http://www.baidu.com/update/app_random_name.app",
    "update_log": "更新日志内容，支持换行，默认是空字符串",
  }
  ```
  其中 version 是当前软件的版本号，download_url 是软件的下载地址，update_log 是更新日志内容；
  当检测到新版本号大于当前软件版本号时，会**静默下载**新版本的软件，下载完成后不会立即安装，因为用户可能在使用；
  软件下次启动时如果检测到有新版本且已完成下载，则**提示用户新的安装程序已经下载完成是否需要立即安装**，用户点击立即安装则进入安装流程，否则用户可以继续使用当前版本。
