由于公司很多项目都是web项目，但是又会遇到需要程序外壳的情况，比如点餐平板、自助平板、电子签名等需求，这时候就需要一个程序外壳来包裹web项目。

本项目用于解决此基础需求，以下是功能清单：

## 启动初始化

- 启动时，首先打开设置页，设置页支持以下配置：
  1. 项目名称 （字符串）
  2. 项目ID （字符串）
  3. 项目URL （字符串，软件启动时需要加载哪个web项目的URL）
  4. 软件运行时产生的日志的保存路径 （字符串，默认是软件启动目录的 ./logs/）
  5. 是否每次启动都全屏 （布尔值，默认是False）
  6. 是否每次启动都置顶 （布尔值，默认是False）
  7. 软件窗口是否展示边框 （windows程序用于展示标题、关闭按钮等的顶部边框，布尔值，默认是True）
  8. 附加信息 （长文本输入框，字符串，支持换行，默认是空字符串，用于输入一些json之类的内容，web项目各种各样，web应用可以通过与软件通信来获得这个附加信息，并通过附加信息来配置任何专属信息）
  9. 是否支持多开软件 （布尔值，默认是False，即只能启动一个软件实例，再次尝试启动软件时会让已启动的软件获得焦点；为true时则允许多开）
  10. 自动更新地址 （字符串，默认是空字符串，用于自动更新软件，比如可以设置为 http://localhost:8080/update/）
  11. 启动时是否打开devtools调试控制台工具 （布尔值，默认是False）

  配置完成后需要将以上配置保存为配置文件，以后启动不再弹出设置页直接根据配置文件进入对应的URL；
  如果无配置文件则依然要打开设置页，用户可以通过手动删除配置文件来重新配置软件；
  其它配置项可以尝试帮我想想，尽可能地让软件提供多的通信API以便适配各种各样的web项目。

## 通信

- 软件与web项目之间的通信，web应用可以与软件互相发送消息来支持以下内容：
  1. web to 软件，关闭软件（退出程序）
  2. web to 软件，最小化软件
  3. web to 软件，最大化软件
  3. web to 软件，全屏
  4. web to 软件，向软件发送一些字符串并保存日志
  5. web to 软件，让软件获得或失去焦点
  6. web to 软件，置顶或取消置顶软件
  7. web to 软件，获取软件所有配置信息（包括附加信息）
  8. web to 软件，让软件打开或关闭devtools调试控制台工具
  9. web to 软件，获取设备信息（比如屏幕分辨率、屏幕尺寸等、CPU等等）
  10. web to 软件，让软件执行任意外部程序。软件自身只是一个web浏览器外壳，但是一些web项目要想运行可能还需要与第三方exe\cmd\bat等程序进行通信，这些web项目可以通过通信来让软件启动、执行任意目录下的任意程序

  以上由web发起的通信，如果相关内容和软件配置项相关，则需要同步修改配置项并更新配置文件；
  其它通信内容可以尝试帮我想想，尽可能地让软件提供多的通信API以便适配各种各样的web项目。

## 性能与健壮性

- 若无web影响，软件应该尽可能地保持良好的性能，最好可以秒启动
- 尽可能地避免软件在运行时崩溃或异常退出

## 安装程序

- 软件最终应该可以被打包为一个exe安装程序，以便于交付给客户

## 软件自动更新

- 示例：假如初始化时填写的自动更新地址是 "http://www.baidu.com/update/",
  则软件启动时会尝试获取该地址下的 version.json 文件比如 "http://www.baidu.com/update/version.json"
  下面是这个json文件的格式：
  ```json
  {
    "version": "1.0.3",
    "download_url": "http://www.baidu.com/update/app_random_name.exe",
    "update_log": "更新日志内容，支持换行，默认是空字符串",
  }
  ```
  其中 version 是当前软件的版本号，download_url 是软件的下载地址，update_log 是更新日志内容；
  当检测到新版本号大于当前软件版本号时，会**静默下载**新版本的软件，下载完成后不会立即安装，因为用户可能在使用；
  软件下次启动时如果检测到有新版本且已完成下载，则**先退出程序并自动安装新版本，安装完成后自动启动**，
  要实现这个功能可能需要外置程序因为软件关闭后可能就无法执行安装和自启了。
