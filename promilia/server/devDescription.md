## 项目概述

基于该环境新建 Java 后端服务项目，包含两个核心模块：邮箱收发服务、用户认证 & 用户信息管理系统。
**不开发前端页面，所有接口逻辑、正向 / 反向场景，全部编写自动化测试用例，要求所有用例执行通过。**

### 模块 1：邮箱收发服务

独立封装邮件工具服务，提供邮件发送、邮件接收能力，供用户认证模块调用；支持普通文本邮件、带验证码 / 重置链接的 HTML 模板邮件；统一异常处理（发送失败、连接超时、邮箱服务商限流等），发送失败需要记录日志，支持重试策略。

### 模块 2：用户认证与用户资料系统

用户账号以邮箱作为唯一账号标识，密码作为登录凭证。全部验证码、临时凭证存入 Redis，设置过期时间，计时清理过期数据，持久化业务数据存入 MySQL。

#### 注册流程

1. 用户提交：邮箱、昵称、图片验证码
2. 服务端校验图片验证码，校验失败直接返回错误；校验通过后，生成 6 位【大写字母 + 数字混合】邮箱验证码，存入 Redis，有效期 5 分钟
3. 向用户邮箱发送邮件，携带该 6 位验证码
4. 用户提交：邮箱、邮箱验证码、密码、昵称
5. 校验：邮箱验证码是否存在、是否过期、是否匹配；校验昵称唯一性；昵称重复返回业务错误；全部校验通过，完成账号注册，密码加密存储，创建用户基础记录

> 
> 限制：邮箱一个短时间内限制频繁发送验证码，防止轰炸

#### 登录流程

1. 入参：邮箱、密码、图片验证码
2. 同时校验三项：图片验证码、邮箱是否存在、密码是否匹配；任意一项不匹配返回错误
3. 校验通过后颁发登录凭证（Token），携带过期时间，用于后续需要登录的接口鉴权

#### 忘记密码（重置密码）流程

1. 用户提交邮箱 + 图片验证码，校验图片验证码合法
2. 校验邮箱是否存在已注册账号；账号存在则生成唯一密码重置 Token，存入 Redis，设置有效期（例如 15 分钟），生成重置链接，通过邮件发送给用户
3. 用户携带重置 Token 访问重置接口，提交：新密码 + 图片验证码
4. 校验图片验证码、校验 Token 是否存在、是否过期、是否和邮箱绑定；校验通过，更新数据库加密密码，Token 立即失效（一次性）

#### 登录后 - 用户资料完善接口（需要登录鉴权）

可修改字段：

- 头像：文件上传，单文件最大 2MB；仅允许图片格式（jpg/png/webp）；文件存储后，数据库记录头像访问路径
- 个性签名：最多 50 个字符
- 生日：日期类型（yyyy-MM-dd）
- 年龄：数字，范围 0 ~ 120，不可手动输入修改，可根据生日自动计算（可选）
- 性别：枚举【男 / 女 / 未知】
- IP 所在地：根据请求客户端 IP 自动解析、自动填充，**用户不可修改**

> 
> 补充约束：
> 
> 
> - 密码必须加密存储，禁止明文；
> - 图片验证码、邮箱验证码、重置链接 Token 均为一次性，验证成功后立即删除；
> - 所有接口做参数合法性校验、防重复提交、限流防刷；
> - 头像文件单独存储，不存数据库大字段；
> - 所有业务异常定义统一错误码，日志完整记录。
