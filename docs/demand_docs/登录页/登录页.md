# 用户注册、登录、找回密码及首页需求文档

## 文档说明

本文档为**用户身份认证全流程**
前端+后端开发需求，明确页面功能、交互规则、数据校验、数据库操作、接口适配等核心要求，基于指定Flutter前端项目、用户数据表结构、后端UserController接口开发，确保前后端逻辑统一、功能闭环、体验合规。

## 基础知识文档

开发前需要知道的基础知识：

- [用户数据表结构](/source/database/sakiko/user_useable.sql)
- [前端开发规范](/docs/dev_docs/frontendSpec.md)
- [后端服务接口定义文件](/source/backend/src/main/java/com/wiki/controller/UserController.java)

## 基础约定

1. **前端环境**：以`/source/fronted`目录为根目录初始化的**Flutter项目**，必须集成**全局数据存储**（用户信息、令牌、状态）、*
   *界面路由管理**（页面跳转、权限拦截）能力；
2. **后端适配**：基于现有`UserController.java`接口调整，补充缺失接口、完善参数校验、业务逻辑、返回值过滤，保证与前端交互兼容；
3. **数据规则**：严格遵循用户数据表字段注释、类型、默认值，所有数据库操作需保证原子性、数据一致性。

## 一、通用基础要求（全页面适用）

1. **网络与异常处理**

- 所有接口请求添加加载状态（按钮禁用、加载动画），请求失败时统一提示（网络错误、服务异常、后端返回错误信息）；
- 表单输入实时校验，输入框聚焦/失焦时触发校验，错误信息实时展示，不等待提交；
- IP获取：前端获取设备公网IP，传递给后端，后端需校验IP格式合法性。

2. **安全与限流**

- 所有限流规则**前后端双重校验**，前端仅做体验优化，后端为最终校验标准；
- 密码、恢复密钥等敏感信息，前端传输需加密，后端不明文存储、不明文返回。

3. **交互体验**

- 按钮点击后立即禁用，防止重复提交；
- 提示信息（成功/错误/倒计时）清晰直观，自动消失或手动关闭；
- 页面适配移动端/桌面端，布局美观、操作便捷。

## 二、注册页面（Register Page）

### 核心功能

用户通过填写表单完成账号注册，满足校验规则后创建用户信息，记录注册IP，生成专属恢复密钥。

### 表单字段（必填/选填明确）

| 字段名                  | 类型       | 必填   | 规则说明                                                                         |
|----------------------|----------|------|------------------------------------------------------------------------------|
| 用户名                  | 文本输入     | ✅ 是  | 1. 不可与数据库中已存在用户名重复；2. 后端实时校验唯一性                                              |
| 密码                   | 密码输入     | ✅ 是  | 1. 长度≥8位；2. 必须包含**英文+数字**，支持英文、数字、符号混搭；3. 前端实时校验格式                           |
| 生日（birthday）         | 日期选择     | ❌ 选填 | 不填写则默认值为**注册当前日期**                                                           |
| 性别（gender）           | 单选/下拉    | ❌ 选填 | 选项：1-男、2-女、3-未知；不填写则默认值为2（遵循库表注释）                                            |
| 密码恢复密钥（recovery_key） | 文本输入（只读） | ✅ 是  | 1. 禁止手动输入，仅前端自动生成/刷新；2. 长度动态区间：20~40位；3. 字符组合：英文+数字+符号；4. 右侧配**刷新按钮**，点击重新生成 |

### 功能与交互规则

1. **表单校验**

- 校验失败时，错误信息**直接展示在对应输入框下方**，红色字体提示；
- 所有必填项未填写、格式不合法，注册按钮**永久禁用**，校验通过后才可点击。

2. **注册限流**

- 注册行为10秒内最多触发1次；
- 前端展示倒计时（如“10秒后可再次注册”），倒计时结束前按钮禁用；
- 后端拦截10秒内重复注册请求，返回错误提示。

3. **注册成功逻辑**

- 后端将用户**注册IP**写入数据库对应字段；
- 前端弹出「注册成功」提示，**3秒后自动跳转至登录页**；
- 注册成功后清空所有表单数据，恢复初始状态。

4. **恢复密钥专属功能**

- 输入框下方提供「复制恢复密钥」文本按钮，点击将密钥复制到用户剪贴板，复制成功提示「密钥已复制」；
- 刷新密钥时，自动清空剪贴板旧密钥，同步更新输入框内容。

5. **页面按钮**

- 主按钮：「注册」（校验通过、倒计时结束后可点击）；
- 文本按钮：「已有账号？点此登录」（点击直接跳转登录页）。

### 后端补充要求

1. 新增接口：用户名唯一性校验接口（前端实时调用）；
2. 注册接口接收所有表单字段，补全默认值（生日、性别），存储recovery_key、注册IP；
3. 严格校验注册限流、密码格式、密钥格式，失败返回明确错误码+描述。

## 三、登录页面（Login Page）

### 核心功能

用户通过用户名+密码完成身份验证，登录成功后记录信息、存储全局数据，失败则触发锁定规则。

### 表单字段

| 字段名 | 类型   | 必填  | 规则说明          |
|-----|------|-----|---------------|
| 用户名 | 文本输入 | ✅ 是 | 支持数据库中已注册的用户名 |
| 密码  | 密码输入 | ✅ 是 | 匹配对应用户的密码哈希值  |

### 功能与交互规则

1. **登录限流**

- 登录行为60秒内最多触发1次；
- 前端展示倒计时，倒计时结束前登录按钮禁用；
- 后端双重校验，拦截短时间重复请求。

2. **登录校验优先级（后端核心）**
1. 校验`deleted_at`：不为空 → 禁止登录，提示「已被注销的用户名」；
2. 校验`locked_until`：大于当前时间 → 禁止登录，提示「该账户已被锁定，24小时后可重试」；
3. 校验用户名+密码：错误 → `failed_login_count + 1`；
4. 失败次数≥5次 → 设置`locked_until`为**当前时间+24小时**，锁定账户。
3. **登录成功逻辑**

- 后端更新：登录IP（覆盖旧记录）、`last_login_time`、重置`failed_login_count`为0；
- 后端返回：**剔除敏感字段**（password_hash、recovery_key）的用户全量信息+用户令牌；
- 前端：将非敏感用户信息存入**全局数据存储**，令牌存入本地缓存（持久化）；
- 自动跳转至首页（首页无需登录即可访问）。

4. **登录失败逻辑**

- 密码错误：提示「用户名或密码错误」，剩余可试次数（5-当前失败次数）；
- 账户锁定：明确提示锁定时长；
- 注销用户：固定提示「已被注销的用户名」。

5. **页面按钮**

- 主按钮：「登录」（校验通过、倒计时结束后可点击）；
- 文本按钮1：「还没有账号？去注册」（跳转注册页）；
- 文本按钮2：「忘记密码或用户名」（跳转找回密码/用户名页）。

### 后端补充要求

1. 登录接口严格执行校验优先级，返回标准化错误码；
2. 禁止返回password_hash、recovery_key等敏感字段；
3. 登录成功生成有效令牌，支持后续身份校验。

## 四、找回密码/用户名页面（Retrieve Account Page）

### 核心功能

支持**找回用户名**、**重置密码**两大场景，通过恢复密钥验证身份，保障账户安全。

### 表单字段（动态展示，按场景切换）

#### 1. 重置密码（二选一验证方式）

| 字段名      | 类型   | 必填  | 规则                           |
|----------|------|-----|------------------------------|
| 用户名/用户ID | 文本输入 | ✅ 是 | 二选一填写：用户名 或 用户ID             |
| 账户恢复密钥   | 文本输入 | ✅ 是 | 需与数据库中该账户的recovery_key完全匹配   |
| 新密码      | 密码输入 | ✅ 是 | 同注册密码规则：≥8位，英文+数字混搭          |
| 确认新密码    | 密码输入 | ✅ 是 | 必须与新密码完全一致                   |
| 新恢复密钥    | 只读输入 | ✅ 是 | 前端自动生成（20~40位英文数字符号），支持刷新/复制 |

#### 2. 找回用户名

| 字段名  | 类型   | 必填  | 规则        |
|------|------|-----|-----------|
| 用户ID | 文本输入 | ✅ 是 | 填写正确的用户ID |

### 功能与交互规则

1. **重置密码**

- 支持两种验证方式：「用户名+恢复密钥」/「用户ID+恢复密钥」；
- 验证通过后：更新密码（生成新哈希）、更新`password_updated_at`、更新为新的recovery_key；
- 重置成功：弹出提示，**自动跳转至登录页**；
- 验证失败：提示「用户名/ID或恢复密钥错误」。

2. **找回用户名**

- 仅支持「用户ID查询」，输入正确ID后，直接展示对应用户名（脱敏展示或完整展示，建议完整）；
- 无结果：提示「该用户ID不存在」。

3. **页面按钮**

- 主按钮：「保存」（重置密码/确认找回）；
- 次要按钮：「取消」（点击直接返回首页）。

### 后端补充要求

1. 新增接口：ID查询用户名、密钥验证+密码重置、密码重置后更新密钥；
2. 重置密码后，强制让用户重新登录，原有令牌失效。

## 五、首页（Home Page）

### 核心功能

公共访问页面，无需登录即可打开，作为应用入口。

### 开发要求

1. 页面为空占位，添加基础布局（顶部标题、中间占位容器、底部导航）；
2. 顶部展示当前登录状态（未登录显示「去登录」，已登录显示用户名）；
3. 预留后续功能扩展入口，无业务逻辑。

---

## 六、全局数据存储与路由要求

### 1. 全局数据存储

- 存储内容：用户非敏感信息（用户名、ID、性别、生日、last_login_time等）、登录令牌、登录状态；
- 存储方式：Flutter持久化存储（如shared_preferences）+ 全局状态管理（Provider/Bloc）；
- 数据同步：登录后写入，注销后清空，修改密码后更新。

### 2. 界面路由

- 路由列表：登录页、注册页、找回密码页、首页；
- 路由拦截：已登录用户访问登录/注册页，自动跳转首页；未登录用户不拦截任何页面；
- 跳转规则：页面跳转无卡顿，支持返回、自动跳转。

---

## 七、前后端接口统一规范

1. **请求格式**：前端统一传参（JSON格式），携带IP、设备信息；
2. **返回格式**：后端统一返回结构（code: 状态码，msg: 提示信息，data: 数据）；
3. **状态码定义**：

- 200：成功；400：参数错误；401：未登录/令牌失效；403：限流/锁定/无权限；404：用户不存在；500：服务异常。

---

## 八、补充优化点（提升体验&安全性）

1. 密码输入框支持「显示/隐藏密码」开关；
2. 恢复密钥生成后，强制提示用户「请妥善保管，用于找回密码，平台无法找回」；
3. 注册/登录/重置密码成功后，自动清除敏感输入框内容；
4. 后端对recovery_key做加密存储，提升账户安全性；
5. 前端添加输入框内容防抖，减少无效接口请求。

---

### 文档完善总结

1. **补全缺失逻辑**：明确校验优先级、字段默认值、敏感信息处理、路由拦截规则；
2. **统一标准**：定义前后端接口规范、状态码、通用交互规则，避免开发歧义；
3. **提升体验**：补充加载状态、复制提示、防抖、脱敏展示等细节；
4. **强化安全**：强调双重限流、敏感字段过滤、密钥加密、锁定机制；
5. **闭环需求**：覆盖注册→登录→找回密码→首页全流程，无功能遗漏。
